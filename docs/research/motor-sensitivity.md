# Motor sensitivity sweep

Generated by `node tools/motor-sweep.ts`. Do not edit by hand; regenerate.

**Kill rule (Tom, DECISIONS 2026-08-30):** no profile constant is ever tuned to make anything pass. This sweep reports bands. It overrides one value at a time on an in-memory clone of `MV601-REF-A` and never changes `data/profiles/*.json`.

## Method

- One axis at a time; every other value stays at the shipped profile. The shipped value is always a grid point.
- Cases per grid point: every entry of `MOTOR_CLAIMS` (`tools/motor-claims.ts`, each resting on a verbatim printed sentence), and every fixture that wires D16-D19 or is tier C1/C2. A fixture passes with zero expectation failures; digests are ignored.
- Printed and speculative fixtures are reported separately. A speculative digest-only C2 fixture has no expects, so it passes at every grid point trivially; its verdict is NO-EXPECTS and it says nothing about the profile.
- A band is a maximal run of consecutive passing grid points. An invalid point (the overridden profile fails `loadProfile`) ends a run and is listed per axis, never skipped.
- ROBUST: the shipped value passes, is more than one grid step from any band edge, and its band covers at least half the valid axis. FRAGILE: it passes but misses either condition. FAILS-AT-SHIPPED: the shipped value fails. NO-EXPECTS: a fixture with zero expects, which cannot fail; it is not a sensitivity result.
- Coverage counts nominal grid points only; the inserted shipped value, when it is off the grid, is not counted.
- A band edge is a band end next to a failing point. The axis end and an invalid neighbour are not edges. Distance is measured in value from the shipped value to the band end point.
